# Oracle DDL

Target Oracle 19c+ (identity columns need 12c+, native `JSON` needs 21c+,
native `BOOLEAN` in SQL needs 23c+).

## Type mapping

| Logical type | Oracle | Notes |
|---|---|---|
| short text | `VARCHAR2(n CHAR)` | Always write `CHAR`, otherwise `n` counts **bytes** and multi-byte text truncates |
| long text | `CLOB` | |
| integer | `NUMBER(10)` | `INTEGER` is an alias for `NUMBER(38)` |
| big integer | `NUMBER(19)` | |
| decimal / money | `NUMBER(12,2)` | Never `BINARY_DOUBLE` for money |
| boolean | `NUMBER(1) CHECK (col IN (0,1))` | Native SQL `BOOLEAN` only from 23c |
| date | `DATE` | **`DATE` includes hours/minutes/seconds** - use a check or trunc if you mean date only |
| timestamp | `TIMESTAMP(6) WITH TIME ZONE` | Or `WITH LOCAL TIME ZONE` for session conversion |
| time | (none) | Use `INTERVAL DAY TO SECOND`, or a timestamp with a fixed date |
| uuid | `RAW(16)` | `SYS_GUID()` generates one; `VARCHAR2(36)` if readability matters more |
| json | `JSON` (21c+) | Earlier: `CLOB` + `CHECK (col IS JSON)` |
| enum | `CHECK (col IN (...))` | No native enum type |
| binary | `BLOB` | |

## Identity

```sql
id NUMBER(19) GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY
```

`GENERATED ALWAYS` refuses explicit values, which breaks many data loads;
`BY DEFAULT ON NULL` is the pragmatic choice. Before 12c the pattern was a
sequence plus a `BEFORE INSERT` trigger - only write that for a legacy database.

## Identifiers

- Unquoted identifiers fold to **UPPER CASE**. Write them unquoted and lower
  case in scripts for readability; Oracle stores them uppercase. Never use
  quoted mixed-case identifiers - every query then needs quotes forever.
- 128 bytes from 12.2; **30 bytes** before that. Legacy databases therefore need
  short constraint names - check the version before generating long names.
- Reserved words: `date`, `number`, `level`, `size`, `comment`, `session`,
  `access`, `audit`, `resource`, `uid`.

## Constraints and indexes

```sql
CONSTRAINT orders_customer_fk FOREIGN KEY (customer_id) REFERENCES customers (id),
CONSTRAINT orders_status_chk  CHECK (status IN ('pending','confirmed','declined','cancelled'))
```

- Foreign keys support `ON DELETE CASCADE` and `ON DELETE SET NULL`. There is no
  `ON DELETE RESTRICT` keyword - **restriction is the default** when no clause
  is given, and there is no `ON UPDATE` clause at all.
- **Always index the foreign key column yourself.** Oracle does not create one,
  and an unindexed FK causes table-level locks on parent modification.
- A `UNIQUE` constraint treats `NULL`s as distinct, so several rows may hold NULL
  in the unique column - which is what makes the soft-deletion pattern work:

```sql
-- Unique among rows that are still active: NULL for retired rows
active_email VARCHAR2(255 CHAR) GENERATED ALWAYS AS (CASE WHEN deleted_at IS NULL THEN email END) VIRTUAL,
CONSTRAINT customers_email_active_key UNIQUE (active_email)
```

## Timestamps

```sql
created_at TIMESTAMP(6) WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL,
updated_at TIMESTAMP(6) WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL
```

No auto-update: add a `BEFORE UPDATE` trigger or set it in the application.

## Canonical example

```sql
-- Derived from features/checkout.feature (REQ-1042, REQ-1043)
-- Assumptions: identity NUMBER(19) keys; timestamps with time zone; single currency per order.
CREATE TABLE products (
  id         NUMBER(19) GENERATED BY DEFAULT ON NULL AS IDENTITY,
  sku        VARCHAR2(32 CHAR)  NOT NULL,
  name       VARCHAR2(255 CHAR) NOT NULL,
  price      NUMBER(12,2)       NOT NULL,
  created_at TIMESTAMP(6) WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL,
  CONSTRAINT products_pk       PRIMARY KEY (id),
  CONSTRAINT products_sku_key  UNIQUE (sku),
  CONSTRAINT products_price_ck CHECK (price >= 0)
);

CREATE TABLE customers (
  id         NUMBER(19) GENERATED BY DEFAULT ON NULL AS IDENTITY,
  email      VARCHAR2(255 CHAR) NOT NULL,
  created_at TIMESTAMP(6) WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL,
  CONSTRAINT customers_pk        PRIMARY KEY (id),
  CONSTRAINT customers_email_key UNIQUE (email)
);

CREATE TABLE orders (
  id           NUMBER(19) GENERATED BY DEFAULT ON NULL AS IDENTITY,
  customer_id  NUMBER(19)   NOT NULL,
  status       VARCHAR2(16 CHAR) NOT NULL,
  total_amount NUMBER(12,2) NOT NULL,
  currency     CHAR(3 CHAR) DEFAULT 'JPY' NOT NULL,
  placed_at    TIMESTAMP(6) WITH TIME ZONE DEFAULT SYSTIMESTAMP NOT NULL,
  CONSTRAINT orders_pk          PRIMARY KEY (id),
  CONSTRAINT orders_customer_fk FOREIGN KEY (customer_id) REFERENCES customers (id),
  CONSTRAINT orders_status_ck   CHECK (status IN ('pending','confirmed','declined','cancelled')),
  CONSTRAINT orders_total_ck    CHECK (total_amount >= 0)
);
CREATE INDEX orders_customer_idx ON orders (customer_id, placed_at);

CREATE TABLE order_items (
  order_id   NUMBER(19)   NOT NULL,
  product_id NUMBER(19)   NOT NULL,
  quantity   NUMBER(10)   NOT NULL,
  unit_price NUMBER(12,2) NOT NULL,
  CONSTRAINT order_items_pk         PRIMARY KEY (order_id, product_id),
  CONSTRAINT order_items_order_fk   FOREIGN KEY (order_id)   REFERENCES orders (id) ON DELETE CASCADE,
  CONSTRAINT order_items_product_fk FOREIGN KEY (product_id) REFERENCES products (id),
  CONSTRAINT order_items_qty_ck     CHECK (quantity > 0)
);
CREATE INDEX order_items_product_idx ON order_items (product_id);
```

The rollback script removes the tables in reverse dependency order; Oracle needs
`CASCADE CONSTRAINTS` on a parent whose children still reference it.

## Pitfalls

- **`DATE` is a timestamp.** A `DATE` column compared with `= DATE '2026-09-08'`
  misses rows with a time component. Use `TRUNC()` or a real timestamp column.
- **`VARCHAR2(n)` counts bytes by default.** In a UTF-8 database, 255 bytes is
  fewer than 255 characters. Always write `(n CHAR)`.
- **The empty string is NULL.** Oracle cannot distinguish `''` from `NULL`, so a
  scenario expecting a blank-but-present value cannot be modelled as an empty
  string - flag this when the specs rely on it.
- DDL commits the current transaction implicitly, so a migration cannot be
  wrapped in one transaction. Keep each migration one logical change.
- Case-insensitive uniqueness needs a function-based unique index on
  `LOWER(email)`, or the session parameters `NLS_COMP`/`NLS_SORT`.

## Optimistic locking

Oracle exposes `ORA_ROWSCN`, the system change number of the row's last commit:

```sql
SELECT ORA_ROWSCN, o.* FROM orders o WHERE id = :id;
UPDATE orders SET status = 'confirmed'
WHERE id = :id AND ORA_ROWSCN = :scn;
```

By default this is tracked per *block*, not per row, so an unrelated row in the
same block moves it and you get false conflicts. It is only row-accurate when the
table was created `ROWDEPENDENCIES`, which cannot be turned on afterwards - the
table has to be rebuilt. Decide at creation time or do not rely on it.

The portable choice, and what ORMs expect:

```sql
ALTER TABLE orders ADD version NUMBER(19) DEFAULT 1 NOT NULL;
UPDATE orders SET status = 'confirmed', version = version + 1
WHERE id = :id AND version = :version;
```
